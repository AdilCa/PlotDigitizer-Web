# PlotDigitizer Web 版架构方案

> 版本：v1.3　日期：以仓库为准
> 定位：在全新项目中重写图表数字化工具，**保留核心算法，不继承现有架构**。
> 依据：`audit-code-bloat.md` 与 `audit-ux-friction.md` 两份审计报告（同目录；所有设计决策均可回溯到其中的编号条目，原件位于 C++ 项目根目录的 docs/ 下）。
> 最新变更记录见文末第 11 章。

---

## 0. 决策：重开新任务，而非在项目内重写

**结论：重开新任务（greenfield），当前 C++ 项目冻结为参考实现。**

理由：

1. **审计证明问题在架构层而非算法层。** 卡手诊断的 5 个根因（状态双轨、级联缺失、无撤销兜底、模态反馈、门控混乱）全部源于 `WizardController` + 多 Overlay + Bridge 的架构设定；核心算法（AxisFitter / TickFitter / Refine）本身只有几百行且健康。在旧代码库上重写，必然把这套"控制器-叠加层-桥"的结构连同坏习惯一起搬过去。
2. **技术栈完全不同**（Qt Widgets/QML → Web 平台），没有可逐行保留的 UI 代码，"在项目基础上重写"实际收益为零。
3. **要保留的只是资产，不是结构**（v1.1 修订：本项目与 C++ 版完全脱钩，不再追求文件格式兼容）：
   - 核心算法的数学逻辑（本文件第 4 章以伪代码固化，作为新实现的规格）
   - 测试图片（C++ 项目 `../test/` 目录中的样例图，如 test1.png / test2.png，作为新项目的固定测试夹具）
   - 两份审计报告（作为新架构的"负面清单"，见第 2 章设计铁律）

C++ 项目此后只做维护性修复，新功能全部在 Web 版开发。

## 1. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript（严格模式） | 状态机+算法代码，类型即文档 |
| 构建 | Vite | 标准、快 |
| UI 框架 | React 18（无 UI 组件库） | 面板/工具条自定义度高，设计系统自己管 |
| 状态管理 | Zustand（单一 store） | 轻量；配合 immer 做不可变更新 |
| 渲染 | **自研 Canvas 2D 渲染器**（不用 Konva/PixiJS） | 需求特殊：像素级对齐、像素坐标与屏幕坐标严格区分、调试可视化叠加。框架黑盒反而碍事；渲染代码预计仅 400-600 行 |
| 大图处理 | Web Worker + OffscreenCanvas | 见第 5 章 |
| PDF | PDF.js（Mozilla） | 纯 JS 解析，替代 pdfimages.exe，且支持按区域按 DPI 渲染 |
| 图像处理 | 手写 TypedArray 算法 | 见第 4 章：实际只需要灰度化 + 一维强度扫描，不需要 OpenCV.js（省 ~8MB WASM） |
| 文件导入 | 拖放（drag & drop）+ 文件选择器 | 图片/PDF/.pdproj 直接拖入窗口即加载 |
| 文件导出 | File System Access API | Chromium 原生支持，见 7.3 |
| 测试 | Vitest + Playwright | 算法单测 + 端到端冒烟 |
| PWA | 后期加（Service Worker） | 离线使用，非 M1 必需 |

**明确不引入**：OpenCV.js、Konva/PixiJS、Electron（网页版先用浏览器跑通，桌面壳以后用 Tauri 也可选）。

**浏览器基线**：仅 Chrome / Edge（Chromium），不做跨浏览器兼容，OffscreenCanvas、createImageBitmap 裁剪参数、File System Access API 等现代 API 直接使用。

## 2. 设计铁律（从卡手诊断提炼，开发中不可违反）

每条铁律对应审计报告中的具体事故，代码评审时对照检查。

### 铁律 1：单一数据源（SSOT）

所有可见内容都派生自 store 中的 model。**禁止**"画布一套数据、model 一套数据"的双轨状态。
- 反例（审计 F2.4/F3.1）：C++ 版 overlay 微移画自己的 `m_line`，updateImageViewerOverlays 画 project 的旧值，屏幕上同一根轴分裂成两条。
- 执行方式：渲染层是纯函数 `render(state) → canvas`，自身不持有任何业务数据；交互层只发 intent（"把第 3 个点移到 x+2"），由 store 统一改 model，再触发重绘。

### 铁律 2：派生数据自动级联重算

`dataPoints` 不存储，永远由 `pixelPoints + calibration` **即时计算**（selector 缓存，输入变更自动失效）。校准一旦变更，所有依赖它的数值自动更新。
- 开销说明：每点一次线性映射（1 次乘法、1 次加法），百点规模也是微秒级，每帧重算无压力。
- 反例（审计 F3.3）：C++ 版重拟合轴后不重算 dataPoints，导出数据与表头自相矛盾。
- 推论：**导出永远不可能自相矛盾**——导出读到的就是当前显示的。

### 铁律 3：破坏性操作有预期

- 任何会覆盖既有数据的输入，先给出视觉反馈（高亮将被替换的目标 + 状态栏文字），再执行；"第三下点击静默替换"类行为禁止存在。
- **全程无撤销**（v1.3 简化）：数据操作（点/刻度/轴/刻度值）的误操作由显式的选中/删除/移动兜底，重放成本极低；图像编辑（裁剪）执行前全程预览、执行后不可回退（owner 决定；审计 F6.1 以"重放即可"结案）。
- 反例（审计 F2.3）：刻度替换陷阱。

### 铁律 4：状态全程可见

- 画布上始终画全量已确认内容（点、标记、轴线、刻度），不存在"确认了就不画"的模式。
- 面板显示：当前序列点数、每轴校准状态与映射参数（两点制校准无残差概念，见 4.3）、当前该做什么的一句话提示。
- 反例（审计 F3.1/F3.2/F1.3）：重进步骤清空画布、marker 确认后消失、Review 步空白。

### 铁律 5：错误反馈内联化，永不弹模态框阻断流程

- Fit 失败：在画布上画出扫描带、候选线、内点/外点标记（把 C++ 版 DebugOverlay 的能力作为**默认行为**，不是开发者开关），错误文字出现在状态栏/面板。
- 任何按钮在被点击前就知道自己是否可用（disabled + 原因 tooltip）。
- 反例（审计 F4.1/F4.2）：模态 QMessageBox 循环、Fit 按钮无条件可用。

## 3. 模块设计

> 全新划分，与 C++ 目录**不**一一对应。目录树为建议结构。

```
PlotDigitizer-Web/
  doc/                  ← 本文件
  public/
  src/
    main.tsx
    App.tsx
    state/
      store.ts          # Zustand store：单一数据源
      model.ts          # 类型定义：Project / Calibration / Series
      selectors.ts      # 派生数据：dataPointsOf、calibrationValid、toolEnabled
      commands.ts       # intent 封装
    engine/             # 纯函数算法，零 DOM 依赖，可单测
      gray.ts           # 灰度化（一次性，输出 ArrayBuffer）
      axisFitter.ts     # 轴线精确定位
      tickFitter.ts     # 刻度定位 + 两点制赋值映射
      refine.ts         # 点优化（柱顶边缘 / refine 范围可视化）
      markerBlob.ts     # 散点 refine（颜色分割 + 连通块重心）
      geometry.ts       # 像素↔数据线性映射
    pdf/
      pdfSession.ts     # PDF.js 封装：逐页缩略图、预览、整页按 DPI 渲染、会话缓存
      pdfImport.ts      # 导入 DPI 选项与尺寸计算（不依赖 pdfjs）
    io/
      projectFile.ts    # .pdproj 读写（zip 容器：project.json + image.png）
      mdExport.ts       # Markdown + 标注 PNG 导出
      fileAccess.ts     # 拖放导入 + File System Access API 保存
    render/
      viewport.ts       # 缩放/平移变换（唯一坐标换算入口）
      canvasRenderer.ts # 分层绘制：底图 / 校准 / 数据点 / 调试
      imageCache.ts     # 大图双轨缓存（见第 5 章）
    interact/
      tools.ts          # 工具状态机：三族六种互斥工具（画轴X/Y、标刻度X/Y、取点、图像编辑）
      hitTest.ts        # 命中测试（屏幕空间恒定半径，随缩放换算回图像坐标）
    ui/                 # React 组件层；布局与控件设计见 doc/ui-style 规格，全新设计，不继承 C++ 版布局
    worker/
      imageWorker.ts    # Worker 入口：灰度化、重采样、refine、裁剪、导出截图渲染
```

### 关键架构决策

1. **渲染层与交互层分离**：`interact/` 只产生 intent，`state/` 改 model，`render/` 画 model。C++ 版"每个 overlay 既是视图又是控制器又是数据副本"的三重身份被拆成三个单向依赖。
2. **工具状态机替代"每步一个 overlay 类"**：三族六种互斥工具（画轴 / 标刻度 / 取点，画轴与标刻度各分 X/Y，外加图像编辑）是同一画布上的互斥工具，切换只是 `store.activeTool = 'markTick-x'`。新增交互模式不需要新 widget 层级。
3. **算法层纯函数化**：`engine/` 全部是无副作用函数 `(imageData, params) → result + diagnostics`，诊断信息（扫描带、内点）作为返回值的一部分，渲染层据此画出内联反馈。这直接落实铁律 5。
4. **Worker 无状态协议（v1.2 新增）**：业务 model 只存主线程；Worker 唯一持有的可变状态是图像像素（处理轨）。所有 Worker 请求（refine、导出截图渲染等）自带全参数、返回结果，不依赖 Worker 侧的业务状态，因此不存在主/Worker 数据分叉。裁剪会重建处理轨像素，属一次性操作，执行后无需回退（撤销机制已于 v1.3 取消）。

## 4. 核心算法移植规格（伪代码）

以下算法逻辑从 C++ 版移植（`src/algo/AxisFitter.cpp`、`TickFitter.cpp`、`WizardController::refinePointScatter/Bar`），**修正已知的性能问题**（审计：refine 每点全图转换），并固化输入输出契约。

### 4.1 灰度化（一次性）

```
function toGray(bitmap: ImageBitmap): GrayImage   // 在 Worker 中执行
  // Rec.601 系数，与 cv::COLOR_BGR2GRAY / Qt Grayscale8 一致
  gray[i] = 0.299R + 0.587G + 0.114B
  // 整张图只做这一次；所有后续算法共享该 buffer
```

### 4.2 轴线拟合 AxisFitter

输入：手绘近似线段（**两个端点确定初始轴线**，图像坐标）、gray、垂直搜索半径 `scan±`（默认 35）
输出：精确定位线段（**强制水平/垂直**，横贯全图）+ 诊断（扫描带、全部采样点位置）

```
1. 多步长集成采样：步长 step 从 10 到 20px 逐一遍历，
   每个 step 下沿手绘线均匀取 max(6, 线长/step) 个采样点
2. 对每个采样点，沿垂直于轴的方向在 ±scan 范围内取灰度剖面
3. 剖面对比度门控：max - min < 25 视为该处无轴线，跳过
4. 谷值中心（半深中点法）：找剖面最小值，向两侧扩展至半深
   ((max+min)/2) 处，取左右边界中点为该采样点的轴线位置
5. 全部采样点位置取中位数作为最终轴线位置（天然抗离群，不剔点）
6. 有效采样点 < 4 → 报错（内联反馈，铁律 5）
7. 返回强制水平（X 轴）/ 垂直（Y 轴）的拟合线，横贯图像全宽/全高
```

与 C++ 版 `AxisFitter.cpp` 实际实现一致（v1.2 修正：此前误写为"加权质心 + 任意方向全最小二乘拟合"）。诊断 = 扫描带 + 全部采样点位置（中位数不剔点，无内点/外点之分）。

### 4.3 刻度拟合 TickFitter（两点制，v1.4 修订）

输入：用户点击的近似刻度位置（**恰好 2 个**）、gray、所属轴、沿轴扫描半宽（按轴可调，默认 ±10px）、用户输入的两个刻度值
输出：精确定位刻度中心 + 映射参数 `a, b`（`value = a + b·pos`）

```
阶段一（定位）：两个近似刻度标出后，由面板"拟合刻度"按钮显式触发
  （门控：该轴恰好 2 个刻度已标出才可用，铁律 5）。
  每个点击位置（X 轴刻度为例；Y 轴行列互换）：
  1. 起始行 = 点击所在行；该行无刻度（如点在轴线上）时向两侧逐行找最近的有刻度行（±6 行）
  2. 逐行定位：沿轴方向 ±scanHalf 取剖面，半深 (max+min)/2 以下的连续区段即谷，
     区段中点为该行刻度中心
     - 同一行有 ≥2 个同等深度（≥ 最深谷 75%）的谷 → 报错「窗口内有多根刻度，请调小扫描窗口」
     - 谷触及窗口边缘 → 报错（被截断，中心不可信）
  3. 长度范围：从起始行向两侧扩展，直到该行不再是同一根刻度（无谷/多谷/中心漂移 >1.5px），≤40 行
  4. 各行中心 3·MAD 剔除离群后取平均 = 刻度在轴线上的投影位置
  拟合成功：刻度吸附到精确位置（空心 → 实心，画布上从点击处移到轴线上）；
  失败：画出扫描区域、逐行定位点与候选线，错误文字上状态栏，不弹窗（铁律 5）
  刻度被移动/增删后，该轴回到"待拟合"态，需重新拟合（刻度值保留）
阶段二（赋值）：拟合完成后输入两个刻度值，解析求解 value = a + b·pos
  （两点确定一直线，无最小二乘、无残差；
    应取轴线上相距最远的两个刻度，减小定位误差影响——owner 工作流）
  对数轴（scaleType = log）：改求解 log10(value) = a + b·pos，
  刻度值必须 >0（内联校验，铁律 5）
返回：a, b, 定位后刻度位置
```

### 4.4 点优化 Refine

`manual` chartType 的序列不调用任何 refine（见 6.3）；以下为 `scatter` / `bar` 的优化算法。

```
refineScatter(pt, patch, bg, r=8):   // v1.6 替换暗度质心（决策 #43）；r = 搜索半径（scatterRadius，默认 8，1–60）
  // 输入：Worker 按 scatterPatchRect 读出的局部 RGBA 块（搜索框外再留 max(24, 2r)，已铺白）；
  //       bg = 全图 4bit/通道直方图峰值色（加载/裁剪时算一次，与窗口位置大小无关）
  1. 搜索框 (2r+1)² 内离点击最近的前景像素（与 bg 距离 ≥ 24）；框内无 → 未吸附「只有背景色」
  2. 沿"与 bg 的距离"爬坡到该物体最浓处，核心 3×3 平均色 = 标记色 c
  3. 掩膜：|p − c| ≤ |c − bg| / 2（半程阈值 = 抗锯齿 50% 覆盖处，边界无偏；别的颜色天然排除）
     覆盖率 α = 1 − |p − c| / |c − bg|
  4. 从核心 4-连通泛洪 → 连通块 S；填孔：不连边框、面积 ≤ πr² 的封闭区 = 空心标记内部
     （同色折线穿过空心圆时内部被切成几块，各块照样填上，圆环变回实心圆盘；一串标记围出的大空白不填）
  5. 孤立且不粘连（内切圆半径 R < 2.5，或面积 ≤ 1.9·πR²）→ α 加权重心
     碰到读取范围边界（连线、成串）或面积过大（几个标记粘在一起）→
       距离变换局部极大 = 各标记内切圆圆心，取 |点击 − 圆心| − R 最小者，
       再在半径 R+1 内迭代求 α 加权重心；R < 2.5 → 未吸附「只碰到线条」
  输出：重心 + 所用像素的凸包（画布绿色轮廓）或未吸附原因（状态栏）
  // 只做单点吸附，不做曲线拟合；被异色标记部分遮挡时取可见部分的重心
  // 取点工具下画布显示作用范围（refineWindow）：
  //   scatter 为 (2r+1)² 搜索框（标记碰到即可），bar 为扫描条带；未确认标记实线框，光标处浅色预览

refineBar(pt, gray, dir=down, span=40):   // v1.2 修订，v1.3 修正，v1.4 修正
  // 扫描方向与范围 span 均为序列级设置（方向上 / 下 / 左 / 右，默认向下；span 默认 40px）
  // 取点总在柱体外、由外向内扫，无需区分暗→亮 / 亮→暗：
  从 pt 沿设置方向取灰度剖面，每个位置为垂直于扫描方向 ±5px 的平均值（抗网纹/噪声）
  找首个 |Δ| ≥ 10 的跳变区段，区段内 |Δ| 最大处（两像素之间的边界）= 柱顶/柱端边缘
  范围内无跳变 → 按原位置提交，状态栏说明「未找到柱边缘」
```

**像素坐标约定（v1.4 新增）**：像素 (i, j) 覆盖连续坐标 [i, i+1)×[j, j+1)，中心 (i+0.5, j+0.5)，与渲染层 `drawImage(0,0)` 一致；所有 engine 算法连续坐标 → 像素下标一律 `floor`，输出连续坐标。

### 4.5 坐标映射 geometry.ts

像素→数据：**每轴独立线性映射 `value = a + b·pos`**，由该轴两个（刻度位置, 刻度值）对解析求解；对数轴在 log₁₀ 域拟合，取数据值时 `10^(a+b·pos)`。**纯函数，由 selector 即时计算**，输入变更自动失效（落实铁律 2）。

**跳过轴语义（v1.1 新增）**：某轴显式跳过时，该轴不存在像素→数据映射；selector 输出的数据点仅含已校准轴的数据坐标，跳过轴在导出中**整列不出现**（见 6.2、7.2）。柱状图等类别轴场景下，类别语义由点命名（点名列）承载。

## 5. 大图双轨渲染策略（专章）

> 背景：PDF 提取的图可达 4000×3000+（RGBA 全解码 ≈ 48MB），而屏幕最多需要 ~2MP。策略核心：**显示轨与处理轨分离，各自按需降载。**

### 5.1 双轨定义

| 轨 | 内容 | 生命周期 |
|---|---|---|
| **显示轨** | `ImageBitmap` 缩略图（长边 ≤ 2048，RGBA ≤ ~12MB）+ 按需生成的"当前缩放级"重采样缓存 | 随 zoom 变化做 LRU 重建；缩放级缓存共享 **128MB 总预算**，超出即淘汰最久未用级 |
| **处理轨** | 原分辨率 `ImageBitmap`（常驻 Worker，不到主线程；**长边 >4096 时灰度化完成后即释放，见 5.4**）+ Worker 中的灰度 `ArrayBuffer`（一次性创建，常驻 Worker） | 随图像加载创建，换图时销毁 |

屏幕绘制只碰显示轨；算法只碰处理轨。**两轨之间唯一的同步点是加载与裁剪**（见 5.3）。

### 5.2 渲染管线

```
主线程 Canvas:
  drawImage(displayBitmap 当前缩放级)        ← 每帧，O(屏幕像素)
  叠加层（校准/点/调试）                     ← 每帧，O(对象数)

Worker (OffscreenCanvas 可选):
  图像加载时：decode → gray 一次
  裁剪确认时：生成新 bitmap 送回
  refine 批量执行：输入点数组，返回优化后点数组
  导出截图：按处理轨分辨率离屏重绘底图 + 标注叠加（见 7.2）
```

- 平移/缩放：仅变换 viewport 矩阵重绘，**不做任何像素运算**
- 缩放级切换：从 `imageCache` 取或 `createImageBitmap(src, {resizeWidth...})` 异步生成，生成期间用就近低级代替（渐进清晰，类似地图）
- **叠加层图形尺寸屏幕空间恒定（v1.2 新增）**：点标记半径、刻度/轴线线宽一律按屏幕像素恒定绘制，**不随缩放变化**；命中测试半径同为屏幕空间恒定值，随缩放换算回图像坐标。由此"两个目标太近时点不准"永远可以用放大图片解决。

### 5.3 裁剪与编辑（大图安全路径）

1. 用户在显示轨上**拖动创建选框，八向手柄调整范围**（类微信截图交互）——**选框是显示轨之上的矢量叠加层，创建与拖动手柄全程实时预览，零像素运算**；Enter / 确认按钮才执行
2. 确认后：主线程把选框外扩为整数像素矩形（floor 起点、ceil 终点、钳制在图内）连同当前图像尺寸发给 Worker——**原图 bitmap 常驻 Worker，主线程不持有、不传输**；请求在途期间确认/工具切换/加载新文件禁用
3. Worker：校验图像尺寸未变 → `createImageBitmap(bitmap, {sx, sy, sw, sh})` + 可选降采样（长边 > 4096 时先缩，控制处理轨内存）→ 重建 gray → 回传新显示轨缩略图与累计裁剪区域（原图坐标，唯一来源）
4. 主线程收到后直接采用 Worker 的区域替换显示轨，旧资源显式 `close()` 释放
5. 全程一次 Worker 往返，主线程零像素运算

### 5.4 内存预算

| 图像尺寸 | 显示轨缩略图 (RGBA) | 处理轨 RGBA 原图 | 处理轨 gray (1B/px) | 常驻合计 | 评价 |
|---|---|---|---|---|---|
| 2000×1500 | ~12MB（原图即不缩） | 12MB | 3MB | ~27MB | 无感 |
| 4000×3000 | ~12MB | 48MB | 12MB | ~72MB | 无感 |
| 8000×6000 | ~12MB | 0（灰度化后释放） | 48MB | ~60MB | 可接受；超此提示用户先裁剪 |

> **处理轨释放分支（v1.2 新增）**：长边 >4096 时，Worker 灰度化完成后立即释放原图 RGBA bitmap；此后需要原图的操作（裁剪、导出高清截图）从源重新解码——文件来源用保留的 File 句柄重解码，PDF 来源用存活的 PDF.js 句柄按区域重新渲染。以一次性 100~300ms 解码延迟换约 200MB 常驻内存。
>
> 注：缩放级重采样缓存另计，共享 128MB 预算，LRU 淘汰；常规使用（局部 2–4 倍放大查看）远低于预算上限。

### 5.5 PDF 导入（v1.5 改为选页弹窗 + 整页导入）

**流程**：打开 PDF 即弹出选页弹窗（页内遮罩层，非浏览器原生对话框）。左侧逐页缩略图（先开窗、逐页渲染出现），右侧所选页大预览，底部选择分辨率（150 / 300 / 600 DPI，默认 300；导入长边超过 10000px 的选项禁用）并显示导入像素尺寸。单击选页，双击缩略图或 Enter 导入，↑↓ 换页，Esc 关闭。

**整页导入，不在弹窗里裁剪**：所选页按 DPI 整页渲染为位图导入画布；只需要其中的图表时，在画布上用图像编辑工具裁剪（6.6，裁剪唯一入口）。不提取 PDF 内嵌图片：论文图表大量是矢量（matplotlib / Origin 直出），没有可提取的嵌入位图，整页渲染对矢量与位图图表都适用。

**PDF 会话缓存（v1.1 新增）**：`PDFDocumentProxy` 句柄与各页缩略图在**加载新 PDF 之前**保持存活，换图（含导入其中一页、恢复 .pdproj）不清除；检查器「PDF」块提供「选择页面…」重新打开弹窗，无需重新解析。从弹窗再次导入 = 加载新图，与 6.6 同一路径（预告后全量重置）；同一 PDF 识别多张图的推荐工作流为"导出 → 选择页面 → 下一张"。

## 6. 状态机与流程设计（v2：无模式工具模型）

> 修订：v1 的"七步向导"废弃。owner 判断步骤框架本身是卡手根源（审计根因①③④均发生在步骤接缝上）。改为无模式工具模型（类 Figma）：全部工具常驻，可用性由 model 状态推导（门控 + tooltip 原因），校准完整性由检查清单呈现。步骤接缝类事故（F3.1 重进步骤丢数据等）随框架消失。

### 6.1 工具模型与门控

三族六种互斥工具（`store.activeTool`）：`drawXAxis / drawYAxis / markTickX / markTickY / extractMarker / imageEdit`。切换工具不清空任何数据（铁律 4）。

**视口控制独立于工具（v1.1 新增）**：滚轮缩放、空格+拖动（或鼠标中键拖动）平移在**所有工具下全程常驻**，校准、取点的任何阶段都可随时缩放平移，不打断当前操作。冲突规则：裸拖动永远归当前工具，平移必须带修饰（空格/中键）。

操作可用性全部由 selector 计算；不可用 = 置灰 + tooltip 原因（铁律 5），工具可用性本身承担引导职能。**门控是唯一校验源：按钮可用 = 操作必然可执行，不存在点击后的二次校验。**

| 操作 | 可用条件 |
|---|---|
| 裁剪图像 | 已加载图像 |
| 画 X / Y 轴 | 已加载图像 |
| 标 X 刻度 | X 轴线已画出且未显式跳过 |
| 标 Y 刻度 | Y 轴线已画出且未显式跳过 |
| 拟合刻度（每轴） | 该轴恰好 2 个刻度已标出且处于待拟合态 |
| 取点（marker） | ≥1 轴已校准（6.2）且有当前序列（新建序列时选定图表类型，6.5） |
| 导出 | ≥1 轴已校准 |
| 重画 / 替换轴 | 已加载图像；执行前有替换预告（铁律 3） |
| 删除轴线 | 该轴已画轴线（面板按钮；或画轴工具下单击轴线选中后 Delete） |

当前工具的可用条件失效时（跳过轴、删除轴线/序列、换图），工具自动回退到画轴工具。

右侧面板顶部的**校准检查清单**永远可见：图像加载状态、每轴四态、序列点数——"还差什么"一眼可见，无需进入任何流程。

### 6.2 轴校准子状态机

每轴独立四态：

```
未设置 ──画出并拟合轴线──▶ 轴线已画 ──2 刻度 + 拟合 + 刻度值──▶ 已校准 ✓
   │
   └────── 显式跳过（每轴独立、与图类型无关）──────▶ 已跳过
```

- **不允许两轴同时跳过**（无坐标语义）；跳过选择写入 calibration 标记，导出中该轴整列不出现（修复 F1.1）
- **"已校准"的完整条件（v1.4 明确）：恰好 2 个刻度、已执行拟合、两个刻度值均已输入，且映射可解**。"轴线已画但刻度不足 2 个 / 待拟合 / 刻度值未赋全" = 警告态：检查清单黄标；取点/导出门控不认其为已校准。都齐了但映射不可解（两刻度拟合到同一位置 / 两刻度值相同 / 对数轴值 ≤0）= "校准无效"，面板与状态栏给出原因
- 刻度被移动/增删后该轴回到"待拟合"警告态，**已输入的刻度值保留**，重新拟合即恢复（4.3）
- 轴可选 `scaleType: linear | log`（面板切换，默认 linear；log 轴刻度值必须 >0，内联校验）；**切换类型时清空两个刻度值**（刻度位置与拟合保留）；对数轴语义见 4.3/4.5
- 重画轴线或删除轴线都级联删除该轴全部刻度及其刻度值（一个逻辑操作）；任何校准返工保留已取点，数据坐标经铁律 2 自动重算（修复 F3.3）
- 换图 = 全量重置 model（修复 F3.4）；同一路径也用于图像编辑确认重置（6.6）

### 6.3 Marker 取点模式（唯一取点交互方式）

- 已确认标记全程持久显示（当前实心 / 已确认 40% 透明度），面板实时"已确认 N 个"（修复 F3.2）
- Confirm 提交当前标记并自动进入下一个
- **批量取点（v1.5）**：面板「批量取点」开关只决定点击空白是追加还是替换未确认标记（切换开关不动已放下的标记）。Confirm 一次提交全部未确认标记：一次 Worker `refinePoints` 请求、按放置顺序编号，状态栏汇总哪些点未吸附；提交时立即取走整批，在途期间新放的标记归下一批。未确认标记可拖动；Delete 撤掉最后一个，Esc 全部取消
- 导出标注截图中每个点旁标出点名（序列色 + 白描边，靠边时翻到另一侧）；画布上不显示点名
- Confirm 时按序列 chartType 决定是否 refine（见 4.4）：
  - `scatter`（面板名「散点」，v1.5 前为「散点/折线」）→ refineScatter 颜色分割 + 连通块重心，搜索半径序列级可调；确认后画布以绿色凸包显示吸附所用像素（仅最近一批，点被移动/删除后消失）
  - `bar` → refineBar（扫描方向与范围为序列级设置，默认向下、40px）
  - `manual` → **不做任何 refine，按标记原位置提交**——用于图上不存在可吸附特征的目标点，典型场景：EIS Nyquist 谱中散点半圆与 x 轴的交点等几何外推位置（v1.2 恢复；v1 误将自由点语义整体废弃，实际只需废弃其独立交互模式，chartType 语义保留）
  - 每次 Confirm 状态栏都报告结果：「已吸附到标记中心 / 柱边缘（移动 x.xpx）」、未吸附原因，或「手动：按点击位置提交，不吸附」（决策 #42）
  - Worker 灰度化前先铺白底：透明像素读回为 (0,0,0,0)，不铺白会被当成纯黑，质心失效（决策 #42）
- **已有点编辑（v1.1 新增，落实 F2.1 设计；v1.4 取消双击抓起）**：
  - **按下**已有点 = 选中（焦点环高亮），方向键按步进移动
  - **按住拖动**超过 3 屏幕像素 = 移动该点（保持按下时的相对偏移；阈值内的手抖不改坐标，不产生新点）
  - **Delete** = 删除选中的点（数据操作的显式删除入口，替代撤销）
  - 步进值面板可调（默认 1px，Shift ×10 粗调）；移动全程触发铁律 2 级联重算，hover 读数即时更新
  - **焦点规则（v1.2 新增）**：文本输入框（点名、步进值、刻度值等）聚焦时，方向键等全局快捷键一律让位文本编辑

### 6.4 刻度操作语义

- 刻度点击：增加即增加（**每轴恰好 2 个；标满后点击空白处不新增**，状态栏提示先删除或移动既有刻度）；点击已有刻度附近 = 选中；拖动 = 移动；Delete = 删除——**不存在"第三个点击替换"**（修复审计 F2.3）
- 刻度显示位置（v1.4）：未拟合画在用户点击处，拟合成功后吸附到轴线上的投影；命中测试按显示位置。拖动已拟合刻度只沿轴移动，拟合起始行保持在原点击行（不会落到轴线上）

> v1.3 起撤销机制整体取消：数据操作由显式选中/删除/移动兜底（铁律 3），裁剪执行后不可回退（6.6）。

### 6.5 多序列

- 取点工具的上下文中提供序列列表（修复审计 F6.3 的隐式 last()）：可新建/重命名/删除/切换，每个序列独立 chartType（`scatter` / `bar` / `manual`；**新建序列时必须选定**，之后可改；柱状序列附扫描方向（上/下/左/右，默认向下）与扫描范围（默认 40px）设置，见 4.4；`manual` 不做 refine，见 6.3）
- 切换 chartType 只影响当前序列后续输入的 refine 方式，不混入其他序列的点
- 典型场景：分组柱状图（如两组 × 四根柱）——序列"组 A"点 4 根柱顶，切换序列"组 B"再点 4 根；类别轴（X）显式跳过，类别语义由点命名承载（见 7.2）

### 6.6 图像编辑（含重置策略）

- 工具：仅**裁剪**——类微信截图交互：拖动创建选框、八向手柄调整范围、Enter / 确认按钮执行；全程显示轨矢量叠加预览，零像素运算。**不提供旋转；对比度/亮度调参功能已于 v1.2 删除。**
- 执行后生成新图像并重建双轨（5.3 节），旧资源显式 close()
- **确认执行 = 新数据提取任务开始**；执行前选框全程为显示轨矢量预览、放弃选框无副作用，执行后不可回退（v1.3 起无撤销）
- 执行时**尚无**校准/取点数据：直接执行
- 执行时**已有**校准或取点数据：先视觉预告"编辑将清除当前校准与已取点"（铁律 3），确认后与换图同一路径全量重置 model——像素坐标系已变更，旧校准无意义
- **加载新图片（v1.1 新增）**：同样先给出"将清除当前校准与已取点"的视觉预告，确认后全量重置

### 6.7 导出（无独立步骤）

- 导出入口常驻检查器底部，门控同取点（≥1 轴已校准）；门控是唯一校验源，按钮可用 = 必然可导出
- 导出格式为 Markdown + 标注截图 PNG（见 7.2）
- 无"Review 步"：已提取点全程高亮可见 + hover 读数，且随时可继续取点——修复 F1.3 的方式是"全部数据全程可见"（铁律 4），而非增加一个步骤

## 7. 文件格式与导入导出

### 7.1 .pdproj（项目文件）

- **store-only zip 容器（v1.2 修订）**，内含两个条目：
  - `project.json`：全新 v1 JSON schema（与 C++ 版脱钩，不兼容旧文件、无迁移路径），schema 随 model 类型定义自然导出，含 `version: 1` 字段供日后演进；内容含校准（含刻度值、scaleType）、序列、点、点名与前缀等 model 全量
  - `image.png`：**编辑烘焙后**的当前图像（裁剪确认即开启新任务，存的当然是新任务的图），恢复时无需重放编辑历史
- **拖入 .pdproj 即恢复完整工程**（图像 + 校准 + 取点）；导入时按 magic bytes（`PK\x03\x04`）区分 .pdproj 与普通图片/PDF
- 不压缩（store-only）：图像本身已压缩，zip 只做打包，读写零编解码开销，体积 ≈ 原图大小

### 7.2 导出：Markdown + 标注截图（v1.1 全新设计，替代 CSV）

导出物为同目录下两个文件：

- `{文件名}-digitized.md`（文件名规则见 7.3）
- `{文件名}-annotated.png`

**标注截图**：Worker 离屏渲染，按**处理轨分辨率**重绘底图 + 全部序列的标记点叠加（按序列着色），与当前屏幕缩放无关，保证清晰度。

**MD 结构**：

```markdown
# {表标题}

![标注截图](xxx-annotated.png)

## 校准信息
X 轴：a=…, b=…, scaleType=linear（或"已跳过"）
Y 轴：a=…, b=…, scaleType=log

## {序列 A 名}
| 点名 | {X 轴数值名} | {Y 轴数值名} |
|---|---|---|
| A1 | … | … |

## {序列 B 名}
…
```

- **跳过轴整列不出现**（含表头）；类别轴场景下点名列充当类别标签
- **点命名**：每序列一个命名前缀（默认取序列名），点自动编号为 `前缀+序号`（A1、A2…）；个别点可在面板点列表中单独改名。改前缀时，仍是自动命名（旧前缀+纯数字序号）的已有点同步改名，手动改过名的点不变；改序列名时，若前缀仍等于旧序列名则一并跟随
- **元信息输入**：导出时检查器底部**内联展开**表单（非模态，铁律 5）：文件名（预填建议名，可编辑）、表标题、每序列点前缀、各已校准轴的数值名称；跳过轴不出现对应输入项；**文件名清空时导出按钮禁用 + tooltip 说明**
- 表格数据由 selector 即时计算（铁律 2），**导出永不自相矛盾**（修复 F3.5）

### 7.3 文件导入与保存路径（v1.1 新增，v1.2 修订）

- **拖放导入**：图片（PNG/JPG 等）、PDF 或 .pdproj 直接拖入窗口即加载；PDF 走 5.5 的识别流程，图片直接建双轨，.pdproj 走 7.1 恢复完整工程。已存在工作时触发 6.6 的全量重置预告（.pdproj 恢复同理）。保留传统文件选择器作为备选入口。
- **导出保存**：浏览器沙箱不允许网页静默写任意路径，Chromium 下的方案：
  1. 默认：`showSaveFilePicker` 弹出保存对话框，建议文件名按下述规则生成；浏览器记住上次目录，第二次导出起默认即停在同目录，一键确认
  2. 可选增强：用户一次性授权目标目录句柄（File System Access API），之后该目录的导出完全静默
  3. 将来套 Tauri 桌面壳后此限制自然消失
- **建议文件名规则（v1.2 统一，v1.2 起不做图号自动识别）**：
  - 图片来源：`{导入文件名去扩展}-digitized`
  - PDF 来源：`{PDF名去扩展}-p{页码}-img{序号}-digitized`（页码与序号为该图在 PDF 中的定位，便于日后检索查验）
- MD 与其标注 PNG 始终写入同一所选目录、共用同一文件名主体
