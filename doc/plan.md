# PlotDigitizer Web 版开发计划（Planlist）

> 版本：v1.0　依据：`architecture.md` v1.3（同目录）
> 用途：greenfield 开发的任务级路线图，可逐项派发执行、逐项勾选。
>
> **使用说明**
> - 任务 ID 规则：`M{里程碑}-{序号}`；状态列：⬜ 未开始 / 🔶 进行中 / ✅ 完成。
> - 「依据」列引用 architecture.md 章节号（§）、设计铁律（铁律 N）、审计条目（F x.y），开发/评审时对照检查。
> - 工时单位：人日；总计 **25.5 人日**，与 architecture.md §8 对齐（多序列 1.0d 计入 §8「数据提取」预算，按 §9 安排在 M5 执行）。
> - 全程无撤销（v1.3 决策）：所有任务不得引入撤销栈；误操作兜底 = 显式选中/删除/移动（铁律 3）。

## 2. 关键路径与并行建议

- **关键路径**：M0 → M1 → M2 → M3 →（M4-6 / M4-7 导出）→ M5 总验收。
- **可并行项**：
  - `engine/` 纯函数算法（M2-1、M2-2、M3-2）零 DOM 依赖，M1-5（gray 就绪）后即可与 UI 工作并行开发、独立单测。
  - PDF 模块（M4-1 ~ M4-3）仅依赖 M1-5/M1-6，可在 M2/M3 期间并行。
  - .pdproj schema（M4-4）在 M1-1（model 类型定义）冻结后即可先行。
- **冻结点**：M1-1 的 model 类型定义是后续所有模块的契约，完成后不轻改。

## 9. 风险与注意事项

1. **PDF.js 与自研 Worker 共存**：pdfjs-dist 自带 worker，与 `imageWorker.ts` 是两个 Worker 实例，注意版本锁定与构建配置（M0-2、M4-1）。
2. **浏览器基线**：仅 Chrome/Edge（OffscreenCanvas、createImageBitmap 裁剪参数、File System Access API 直接使用，不做降级）（§1）。
3. **超大图**：长边 >4096 走 M1-9 释放分支；>8000×6000 提示用户先裁剪（§5.4）。
4. **对数轴数值稳定性**：`10^(a+b·pos)` 大动态范围下的显示精度，M5-4 单测覆盖（§4.5）。
5. **model 冻结**：M1-1 的类型定义是全部后续模块契约，评审通过后再冻结；.pdproj schema（M4-4）与之同源导出。
6. **铁律评审**：每个里程碑门禁评审时对照铁律 1–5 逐条检查，尤其「渲染层不持有业务数据」（铁律 1）与「零模态弹窗」（铁律 5）。
